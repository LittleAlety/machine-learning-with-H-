# C-3 v2 DFT 生产前预检迭代

日期：2026-09-20

迭代状态：**Stage 1 条件放行；Stage 2/3 批次生产未放行**

本轮没有把 CHGNet 或机器学习预测冒充 DFT 结果。计算范围限定为 C-3 v2 上机前的独立预检：重算三个冻结批次、审计预注册哈希链、核对开源 DFT 软件包、提出锚定闸门候选，并复核核时预算。

## 1. 阅读结论

三份文档给出的项目状态一致：

1. 交付文档确认主模型 v3 的分组 OOF MAE 为 0.1134 eV，lockbox MAE 为 0.1103 eV；真实几何信号约 0.025 eV，但因冻结的泄漏闸门判为 LEAK，尚未进入 v5。
2. `C3v2_DFT生产实施方案.docx` 把下一步限定为 45 个体系的 A/B/C 三批 DFT 生产，要求 BEEF-vdW/QE 协议一致、先过 5–10 体系锚定闸门、再做 3 个探针任务核时校准。
3. `AI开源软件方案.docx` 给出的主栈是可落地方案：QE 负责正式能量，MACE/CHGNet 只能做预弛豫，ASE/pymatgen 与 atomate2/FireWorks 负责结构和编排，现有一致性闸门继续负责放行。

因此本轮选择“DFT 生产前预检”作为迭代，而不是在无集群环境中伪造 DFT 计算。

## 3. 计算结果

### 3.1 批次 A：主动学习补点名单可复现

重算结果与冻结名单在组成、结构、晶面和顺序上完全一致，数值差异仅来自冻结文件的四舍五入：

```text
acquisition_score max |difference| = 4.0e-5
pred_dG max |difference|           = 5.0e-5
```

关键统计：

| 指标 | 结果 |
|---|---:|
| 原始主动学习候选池 | 426 |
| 通过域内和红旗过滤的候选池 | 58 |
| 冻结名单 | 10 |
| 入选组成在全体候选中的排名范围 | 16–58 |
| 平均 `|pred_dG|` | 0.0669 eV |
| `|pred_dG| <= 0.05 eV` 的数量 | 4/10 |
| `|pred_dG| <= 0.10 eV` 的数量 | 7/10 |
| 含 Hg/Tc 的高毒或放射性体系 | 4/10 |
| 含 Cr 的体系 | 3/10 |
| 最高成员元素 LOEO MAE | 0.2283 eV，来自 Au |

结论：批次 A 的“采集分数顶部 + 红旗过滤 + 域内”规则可以从本地源文件独立复现。全体候选的前 15 名因红旗或域外被过滤，首个合法候选位于全体第 16 名。该批次确实是残余不确定度导向，而不是近热中性导向；但没有 DFT 结果，不能验证预期的外部误差下降。

按方案中的中点单任务成本、每表面 5 个位点、30% 失败重跑余量重算：

冻结方案写的是约 20 万核时，与本轮重算的 `199,875` 核时相差仅 0.0625%，中点数一致。区间敏感性为：

| 场景 | 核时 |
|---|---:|
| 低端点 + 30% 余量 | 101,400 |
| 中点 + 30% 余量 | 199,875 |

- 32 核并行：约 260.3 天，接近方案中的 9 个月量级。

## 5. 结论

本轮把项目状态从“执行就绪”推进为“预检完成、Stage 1 可启动”，但没有把仓库状态夸大为 DFT 已生产或 v5 已可用。

最重要的四项结论是：

1. A/B/C 三批名单不是人工拼凑，能够从冻结上游数据重算；A 和 B 的规则完全闭合，C 在推断的 `12/1/12` 分层配额下完全闭合。
2. 当前预注册哈希不能自证，必须先补独立校验文件或修正案；这是正式生产前最明确的审计阻断项。
3. 批次 C 的 CHGNet 弛豫能降和表面位移极大，支持其作为“伪影检测实验”的定位，但不支持它直接作为真实构型、材料稳定结论或催化推荐。
4. QE/GPAW/CP2K 源码及 BEEF-vdW 关键依赖已经备齐并校验，但编译、锚定和核时校准尚未完成，因此还不到提交 45 个正式 DFT 作业的时点。

下一步不应先跑 A/B/C，而应按以下顺序执行：

1. 在集群构建 LibXC、libvdwxc、FFTW 和 Quantum ESPRESSO 7.6。
2. 对 9 个锚定候选中的 5–10 个执行 BEEF-vdW 闸门，任何体系超过 0.1 eV 即停机排查。
3. 跑 1 个体相、1 个清洁 slab、1 个吸附弛豫探针并记录真实核时。
4. 补预注册哈希修正案和批次 C 分层配额说明。
5. 上述全部通过后，再按 Stage 2/3 顺序启动 A/B/C，并保留全部失败与阴性结果。
